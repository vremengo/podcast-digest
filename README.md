# Podcast Digest → Telegram

Бот раз на 2 години перевіряє YouTube-канали подкастів. Для кожного нового довгого випуску Gemini робить дайджест українською, і бот публікує його в Telegram-канал. Все працює на безкоштовних тарифах.

```
RSS YouTube ──► YouTube Data API ──► субтитри? ──так──► Gemini (текст)
 (нові відео)   (тривалість, перегляди,        └─ні───► Gemini (відео за посиланням)
                 підписники)                                   │ JSON
                                                               ▼
       Telegram ◄── рендер у шаблон ◄── вік гостей з Wikidata ◄┘
       data/state.json (що вже опубліковано) комітиться назад у репо
```

## Що безкоштовно і які ліміти

| Сервіс | Ліміт |
|---|---|
| Gemini API, безкоштовний тариф | до 8 год YouTube-відео на добу. Ліміти запитів дивись в AI Studio |
| YouTube Data API v3 | 10 000 одиниць на добу. Один запуск витрачає ~5–10 |
| GitHub Actions | для публічного репо без обмежень, для приватного 2000 хв/міс. Один запуск займає ~1–3 хв |
| Telegram Bot API, Wikidata, RSS YouTube | безкоштовно |

> ⚠️ На безкоштовному тарифі Google може використовувати запити для покращення своїх моделей. Для публічних подкастів це не проблема.

## Налаштування (≈15 хвилин)

### 1. Ключ Gemini
[aistudio.google.com/apikey](https://aistudio.google.com/apikey) → **Create API key**. Картку не прив'язуй, тоді ключ залишиться на безкоштовному тарифі.

### 2. Ключ YouTube Data API
1. [console.cloud.google.com](https://console.cloud.google.com) → створи проєкт.
2. **APIs & Services → Library → YouTube Data API v3 → Enable**.
3. **Credentials → Create credentials → API key**. Бажано обмежити ключ тільки YouTube Data API.

### 3. Бот і канал у Telegram
1. [@BotFather](https://t.me/BotFather) → `/newbot` → збережи токен.
2. Створи канал і додай бота **адміністратором** з правом публікувати повідомлення.
3. `TELEGRAM_CHAT_ID`:
   - для публічного каналу це `@назва_каналу`;
   - для приватного — числовий id вигляду `-100…`. Щоб його дізнатися, перешли будь-який пост із каналу боту [@userinfobot](https://t.me/userinfobot).

### 4. Репозиторій на GitHub
1. Створи репо (краще публічне, тоді Actions безлімітні) і залий у нього цю папку.
2. **Settings → Secrets and variables → Actions → New repository secret**. Додай:
   - `GEMINI_API_KEY`
   - `YOUTUBE_API_KEY`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
3. **Settings → Actions → General → Workflow permissions → Read and write**. Це потрібно, щоб бот зберігав `state.json`.
4. За бажанням: вкладка **Variables** → `GEMINI_MODELS`. Це список моделей через кому, наприклад `gemini-3.8-flash,gemini-3.5-flash`. Якщо на першій моделі закінчився ліміт, бот переходить на наступну.

### 5. Перший запуск
1. **Actions → podcast-digest → Run workflow**.
2. Встав посилання на відео й постав галочку **dry_run**. Готовий пост з'явиться в логах, у канал нічого не піде.
3. Якщо все гаразд, запусти ще раз без dry_run. Далі бот працює сам за розкладом.

## Як додати подкаст
Відредагуй `config/channels.yaml`:

```yaml
channels:
  - handle: "@JayShetty"
    name: "Jay Shetty · On Purpose"   # необов'язково
  - handle: "@TheDiaryOfACEO"
```

Там же налаштовуються:
- `min_duration_minutes` — мінімальна тривалість, щоб відсікти shorts і нарізки;
- `lookback_hours` — за скільки годин назад брати нові випуски;
- `max_videos_per_run` — скільки випусків обробляти за один запуск.

## Шаблон і стиль
Пост подається як аналітична новина. Блоки: 🎙 заголовок → 📌 категорія → 📺 канал, тривалість, перегляди, дата → учасники (з коротким «↳ тезою» кожного, якщо вона в них була) → лід → 📊 ЧИСЛА ТА ФАКТИ → 🗣 ОЦІНКИ ТА ПРОГНОЗИ → ⚔️ ДЕ РОЗХОДЯТЬСЯ ДУМКИ → 💬 цитати → 🎯 ЩО З ЦЬОГО ВИПЛИВАЄ → 👀 ЗА ЧИМ СТЕЖИТИ.

Теза під ім'ям учасника — це його особиста позиція саме в цьому випуску (1 речення), а не роль чи факт з розмови. У ведучого її часто немає (він переважно ставить питання) — тоді рядок просто не з'являється.

Перевірювані твердження й особисті оцінки спікерів розводяться по різних блоках: те, що спікер назвав зі своєї голови (прогноз, суб'єктивна ймовірність), не подається як факт.

Біля фактів і цитат може стояти ⏱ з посиланням на момент у відео. Таймкод ставиться лише тоді, коли модель його дала й він не виходить за тривалість випуску; саме посилання веде на 5 секунд раніше, бо таймкоди від моделі бувають неточні.

- **Текст дайджесту:** у `prompts/digest_uk.md`. Там задається стиль заголовка й вимоги до кожного блоку.
- **Вигляд посту:** у `digest/render.py`. Там емодзі й порядок блоків. Якщо пост довший за 4096 символів, він ділиться на кілька повідомлень між блоками.
- Блоки «категорія», «де розходяться думки» та «за чим стежити» необов'язкові: якщо у випуску немає суперечки чи очевидного продовження, вони просто не виводяться.

## Локальний запуск
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt pytest
pytest -q
set -a; source .env; set +a      # скопіюй .env.example → .env
python -m digest --dry-run --video "https://www.youtube.com/watch?v=..."
```

## Як бот поводиться при збоях
- **Вичерпано безкоштовний ліміт Gemini на всіх моделях:** бот зупиняється і доробить решту в наступному запуску.
- **Помилка на конкретному відео:** бот пробує ще раз у наступних запусках, максимум 3 спроби.
- **Субтитри недоступні** (з серверів GitHub YouTube часто їх блокує): Gemini аналізує саме відео, 1 кадр на 10 с у низькій якості.
- **Вік гостя:** показується тільки коли у Wikidata є рівно одна жива людина з таким іменем і точною датою народження.
- **Трансляції:** поки ефір триває, бот їх пропускає і обробляє після завершення.
- **Неактивні репо:** GitHub вимикає cron через 60 днів без активності. Коміти `state.json` зазвичай тримають репо активним. Якщо розклад усе ж вимкнувся, увімкни його у вкладці Actions.
